## Brand & Style

This design system is built upon the **Dynatrace Strato** design language, the official design system for Dynatrace platform applications. It prioritizes clarity, data density, and a cohesive enterprise experience across both light and dark themes. The system is optimized for observability, monitoring, and SRE workflows, where information hierarchy and semantic color usage are critical for rapid scanning and decision-making.

The visual language balances technical precision with approachability, using a **purple-blue primary accent** (`#474fcf` light / `#999bed` dark) as the brand anchor. Semantic colors (success, warning, critical) follow consistent chromatic scales from muted backgrounds to vivid accents, ensuring accessibility and contextual awareness throughout the interface.

All color tokens are theme-aware: the same token name resolves to different hex values depending on whether the app is in light or dark mode, managed automatically by the Strato design token system via CSS custom properties (`--dt-colors-*`).

## Elevation & Depth

The Strato system defines **three surface elevation levels** with distinct shadow styles: Flat, Raised, and Floating. Each has interactive states: Rest, Hover, Active, and Drag.

- **Flat:** Default surface level. No vertical offset, only a 1px border (`0px 0px 0px 1px`). Used for cards and containers.
- **Raised:** Subtle elevation with a 1px border, 1px vertical offset, and 4px blur. Used for hovered interactive surfaces.
- **Floating:** Higher elevation with stronger blur and offset. Used for modals, dropdowns, and popovers.

**Layer elevations (z-index):**
| Layer | Value | Usage |
|-------|-------|-------|
| Default | 1 | Base content |
| Sticky | 10 | Pinned headers |
| Overlay | 20 | Modals, dropdowns |
| Notification | 1999999999 | Toast notifications |

Shadows use semi-transparent black in light mode (`#2d2e4e`) and dark mode (`#112`/`#f0f0f5`) for natural depth perception across themes.

## Components

- **Buttons:**
  - *Primary:* Solid `Theme.Primary['60']` background with white text. Hover transitions to `Theme.Primary['80']` (dark) or `Theme.Primary['40']` (light).
  - *Secondary/Ghost:* Transparent background with `Border.Neutral.Default` outline.

- **Cards & Panels:**
  - Background: `Background.Surface.Default`. Border: `Border.Neutral.Default` (1px solid).
  - Border radius: `Borders.Radius.Surface.Default` (12px).
  - Shadow: `BoxShadows.Surface.Raised.Rest`.
  - Used for data grouping, metric cards, and content containers.

- **Containers:**
  - Neutral containers (Subdued → Emphasized → Accent) for progressively higher visual weight.
  - Primary containers for brand-accented sections.
  - Semantic containers (Success/Warning/Critical) for status-driven content with contextual background colors.

- **Fields (Form Inputs):**
  - Multi-state: Default, Hover, Active, Disabled, Emphasized.
  - Available in Neutral, Primary, Success, Warning, and Critical variants.
  - Border radius: `Borders.Radius.Field.Default` (6px).

- **Badges & Tags:**
  - Pill-shaped (`Borders.Radius.Field.Emphasized` = 9999px).
  - Use semantic container colors for status indication.
  - Typically paired with `Text.*` or `Icon.*` tokens for content.

- **Data Visualization:**
  - 15 categorical colors for chart series and data grouping.
  - Status colors for semantic indicators (ideal → critical).
  - Sequential and diverging palettes for heatmaps and gradient visualizations.
  - Log level colors for observability and monitoring contexts.

- **Code Blocks:**
  - Monospace font: `Roboto Mono`.
  - Syntax highlighting via dedicated `Syntax.*` tokens covering 10 token types.
  - Background typically uses `Background.Container.Neutral.Emphasized` or similar.

- **Dividers & Separators:**
  - Default separator: 1px solid `Border.Neutral.Default`.
  - Can be used as horizontal rules (`Border.Neutral.Default`).
